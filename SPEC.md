# Dharma Studio — specification

A professional comic studio for *The Cycle of Dharma* (Rachit Agarwal, Rishikesh Studio). Runs locally on the
Mac mini (`~/apps/dharma-studio`), opens in the browser at `http://localhost:8787`. Every decision that used to
live in chat — which candidate, what the caption says, how the page is cut, who the character is — lives on a
screen and in the database. Claude prefills; the author decides; nothing is generated for a page until the
characters on it are locked.

Reference look: `docs/samples/spread_a.png`, `docs/samples/spread_b.png` (parchment canvas, torn and crisp
shards, pencil-sketch marginalia, Devanagari marginalia, parchment caption boxes, compass rose, map). Reference
Rama: `docs/samples/rama_reference.png`.

## 1. Screens (left rail, in order — the order is the workflow)

1. **Project** — book, volumes (Book One / Two / Three), chapter list from the manuscript PDF, API keys status
   (read from `.env`, never shown), cost ledger.
2. **Characters** ← *the gate*. One card per character: name, forms (Rama; Hanuman/vanara, Hanuman/vast;
   Ravana/ten-heads, Ravana/young; Shiva/flames …), the **look paragraph**, 1–6 **reference images**, a
   **lock** switch. Generate reference candidates from the look paragraph (Sunburst / Gemini), pick, mark one
   as *primary*. Locked = prompts carry the look paragraph and the primary reference is attached to every
   generation of that character. A page whose panels name an unlocked character cannot generate (the button is
   disabled and says which character is unlocked).
3. **Canvas** — the paper and the page frame per volume. Volume 1 default: *Parchment* (warm, mottled, torn
   margins, ink gutters). Library: Parchment · Palm-leaf (Treta) · Burnt vellum (Lanka) · Indigo night
   (ocean/sky chapters) · Iron (Dwapara, red mud) · Glass (Phala / Core, cool white-blue, gold UI lines) ·
   Khadi (Girgaon/Resistance, cotton weave) · Plain white (proof). A canvas = paper texture + ink colour +
   caption-box style + marginalia style + gutter colour. Volume 2/3 get a suggestion card (Iron, Glass) but the
   author picks.
4. **Script** — manuscript text per chapter on the left (from the PDF); the page list on the right. *Prefill
   pages* asks Claude to break the chapter into pages/panels (captions verbatim from the book, EN; Hindi draft
   column). Every text box of every panel is a field: caption EN / HI, balloon EN / HI, speaker, state
   (quiet/rising/peak/ego/knowledge/voice), beat (calm/tension/action/revelation/hex). Edit inline.
5. **Pages** — the core screen. Left: thumbnails of all pages with status (empty / generating / review /
   approved). Centre: the page rendered as the real layout (same HTML the PDF is made from). Right: the
   selected panel — scene text (the prompt's SCENE line), candidates grid, **feedback** box ("eyes open",
   "wider, no giants") → Claude rewrites the scene line → regenerate N (provider: Sunburst / Gemini NB 2.1 /
   Gemini Pro), pick → the page re-renders. Page tools: beat, re-cut, **shard editor**, marginalia, approve.
6. **Silhouettes** — the marginalia library: pencil-sketch line art (character studies, bows, maces, lotus,
   compass roses, map fragments, temple outlines, Devanagari marginalia). Generated by Sunburst as *ink on
   white, no colour*, auto-keyed to transparent PNG; tagged; drag onto any page margin; also auto-placed by the
   layout from the page's characters. Author can upload their own.
7. **Export** — per chapter or volume: Topaz-upscale the selected images (plates and hero shards), build EN and
   HI PDFs at 170×260 mm + 3 mm bleed with crop marks, 300 ppi JPEG, embedded fonts; download; history.

## 2. Shards (the panel shapes)

A page is a list of panels; each panel has a **shape**. Shapes are editable polygons in page millimetres and
are stored, not recomputed, once the author touches them.

Shape kinds (the editor's palette; the auto-cut chooses by beat):

- `torn` — irregular polygon, edge resampled with paper-tear noise (calm pages; the samples' dominant look)
- `crisp` — straight cuts, small angle (tension)
- `fracture` — diagonal, chipped vertices (action)
- `hex` — honeycomb cell with gold rim (openers only)
- `rect` — plain rectangle with rounded 1 mm corners (classic grid, the sample's lower rows)
- `inset` — circle/oval vignette floating over another panel (the crystal-ball panel in the sample)
- `bleed` — full page plate
- `custom` — any polygon the author draws

Editor: drag vertices, add/remove vertex, snap to margins and to neighbours' gutters, set edge treatment per
shard (torn / crisp / chipped / feathered / rim), set z-order (insets float), set the image's focal point and
scale inside the shard (pan/zoom), lock a shard. Multiple shards may share one image (`image_group`,
revelation beat). The page auto-cut (`visual_logic`) is the starting point; *Re-cut* regenerates it; manual edits
survive re-generation of images.

## 3. Data model (SQLite via SQLAlchemy; one file `studio.db`; images on disk under `data/`)

- `Project(id, title, author, manuscript_pdf, settings json)`
- `Volume(id, project_id, number, title, canvas_id, era_default)`
- `Canvas(id, key, name, paper_texture, ink, gutter, caption_style json, marginalia_style json, preview)`
- `Chapter(id, volume_id, number, title, text, pages_from, pages_to)`
- `Character(id, project_id, name, form_key, look, locked bool, primary_ref_id)`
- `CharacterRef(id, character_id, path, provider, prompt, is_primary, approved)`
- `Page(id, chapter_id, number, beat, status enum[empty,draft,generating,review,approved], canvas_override,
  marginalia json[], seed)`
- `Panel(id, page_id, n, kind, shape json{kind, polygon_mm[], edge, z, focal{x,y,scale}}, image_group,
  scene (prompt scene line), scale (EWS..ECU), state, characters[], caption_en, caption_hi, balloon_en,
  balloon_hi, speaker, hi_is_draft, selected_candidate_id, locked_shape bool)`
- `Candidate(id, panel_id, path, provider, model, prompt_full, feedback_used, cost_usd, created_at,
  qa json, rejected bool)`
- `Silhouette(id, project_id, path, tags[], source enum[generated,uploaded], prompt)`
- `Job(id, kind, ref_id, status, log, cost_usd)` — generation runs in a background worker thread; the UI polls.
- `Ledger(id, provider, usd, ref)`

## 5. Engine (reused from `dharma-pipeline`, vendored as `engine/`)

`visual_logic` (intensity / scale / beat dials), `layout` (SVG clip-paths, shard polygons, bilingual captions,
Devanagari fonts, parchment paper mode, crop marks), `proof.compress_pdf`, `enhance.topaz_upscale`, the prompt
recipe (`COMIC_STYLE / GRADE / LIGHT / CAMERA / SCALE_RULE / WORLD / DUEL / character looks`), providers
(Sunburst generate + edits-with-reference, Gemini Interactions API, Topaz Image API), Claude agents
(`panel_script`, `hindi_draft`, new `scene_rewrite`, new `silhouette_prompt`).

The layout gains: per-panel stored polygons, `inset` and `rect` kinds, focal pan/zoom, marginalia layer
(silhouette PNGs placed in the margins at given mm positions with ink tint), canvas paper textures (an actual
texture image in the page background for screen; for print the paper is the stock and only ink is output —
`paper="print"`), title block for chapter openers.

## 6. Non-negotiables

- No generation for a page with an unlocked character on it.
- Shards mode: Sunburst never draws text; all lettering is typeset. The only permitted in-image glyphs are the word
  राम on Agastya's arrow. Painted-page mode (§10) is the one exception: the lettering is painted and proofread.
- Captions are the book's sentences unless the author edits them in the Script screen.
- Every candidate keeps its full prompt and the feedback that produced it (reproducibility and the ledger).
- Approved pages are frozen: regenerate requires un-approving.
- Keys only from `.env`; never in the DB, never in the UI.

## 7. Build order

1. Backend + engine + seed (Chapter 1 pages/panels, Rama locked with the reference, all canvases).
2. Pages screen with candidates/feedback/regenerate/select and the live render.
3. Characters screen with the lock gate.
4. Shard editor.
5. Script, Canvas, Silhouettes, Export.

## 8. Director models and the onboarding journey (added 2026-10-30)

The studio has three text roles and one image role, each with a selectable model; the choice is stored in
`Project.settings.models` and offered only from providers whose key is present in `.env`:

| role            | what it does                                                        | choices (if key present)                          | default   |
|-----------------|---------------------------------------------------------------------|---------------------------------------------------|-----------|
| `script_writer` | prefill pages/panels from the chapter text; Hindi drafts            | Claude (claude-sonnet-4-5 / claude-opus-4-1), OpenAI (gpt-5 / gpt-5-mini) | Claude    |
| `prompt_writer` | write and rewrite each panel's SCENE line from text + feedback     | Claude, OpenAI                                    | OpenAI    |
| `critic`        | QA a candidate against the scene, the lock and the book (optional) | Claude, OpenAI                                    | Claude    |
| `image`         | paint the panel                                                     | Sunburst (OpenAI), Gemini NB 2.1, Gemini Pro      | Sunburst  |

Both text providers go through one interface `engine/llm.py`: `ask_json(role, system, user, images=[])` → Claude
Messages API or OpenAI Responses API (JSON output), same prompts, same fallbacks. The image providers are
already uniform in `engine/providers.py`.

API: `GET /api/models` → `{providers: {anthropic: bool, openai: bool, gemini: bool, topaz: bool}, roles:
{script_writer: [...], prompt_writer: [...], critic: [...], image: [...]}, selected: {...}}`;
`PUT /api/project/models` `{script_writer, prompt_writer, critic, image}`.

Onboarding journey (first run, and re-enterable from Project → "Start over"):
1. **Upload the manuscript** (PDF or text) → POST `/api/project/manuscript` (multipart) → the server extracts
   text, detects chapters (headings "Chapter N", "Interlude", "Prologue"), creates Volume/Chapter rows, shows
   the chapter list for confirmation (title and page range editable).
2. **Models** — the selector above, built from the keys found; a one-line cost note per image model.
3. **Characters** — the script_writer proposes the cast from the manuscript (name, forms, a first look
   paragraph; POST `/api/characters/propose` → job); the author edits looks, generates/uploads references,
   locks. The journey cannot advance to pages until every character that appears in Chapter 1 is locked.
4. **Canvas** — pick per volume.
5. **Prefill Chapter 1** → Script screen for text edits → Pages.
A stepper at the top of the Project screen shows where the project is; each step is a screen already in §1.

## 9. Director batch (added 2026-10-30)

"Make pages 1–5" in one instruction. `POST /api/director/batch` `{chapter_id, pages: [1,2,3,4,5] | {"next": 5},
candidates_per_panel: 2, provider: "sunburst"|"gemini-nb21"|"gemini-pro", prefill_text: true, run_critic: true,
dry_run: false}` → one Job of kind `batch` with `progress: {page, panel, done, total, cost_so_far}` and a `stop`
flag (`POST /api/jobs/{id}/stop` finishes the current panel and halts). Steps per page, in order:
1. gate check (skip the page with a logged reason if any character on it is unlocked — the batch continues);
2. if the page has no panels and `prefill_text`, the script_writer prefills it from the chapter text;
3. for every panel without a selected candidate: generate `candidates_per_panel` with the chosen image model,
   attaching locked references;
4. if `run_critic`: score the candidates and pre-select the top one (never auto-approve the page);
5. set the page to `review`.
`GET /api/director/estimate` with the same body returns `{panels, images, usd}` before running (Sunburst ≈ $0.04
per 1536×1024 high image; Gemini NB 2.1 ≈ $0.03; Topaz 1 credit per export image). The Pages screen gets a
"Director" button opening this form; the jobs tray shows the batch with its page-by-page progress and Stop.

## 10. Painted-page mode (added 2026-10-31)

The author rejected the composited-shard pages (too dark, too detailed, not parchment). A page now has a **mode**:
`painted` (Volume 1's default) or `shards` (the compositor above), set per volume (`Volume.page_mode`) with a per-page
override (`Page.page_mode`). In painted mode the image model (gpt-image-2.5-sunburst, 1024×1536 portrait, quality
high) paints the WHOLE page in one fixed house style, with large readable lettering inside parchment narration boxes.

- Prompt (`engine/director/painted.py: build_page_prompt`): HOUSE_STYLE (the author's sentence, verbatim) + the
  typography line + the pacing line + a safe-area line + the opener header ("BOOK ONE · n — Title", first page of the
  chapter) + the locked looks (the Character table, as for shards) + every panel in reading order:
  `Panel k (<shot>): <scene>. Narration box: “<exact text>”` / `Speech balloon (<speaker>): “<exact text>”`.
- Box texts are verbatim manuscript excerpts (trimmed at word/clause boundaries or elided with “…”), at most 14 words;
  a longer line is rejected with a message telling the author to split it. Planner-chosen sentences are fitted.
- Text check: the painted page + the expected texts go to the critic model (OpenAI vision via `engine/llm.py`,
  default gpt-6.1-sol, fallback gpt-5.5, selectable per run) for a JSON transcription of every lettered text; quotes,
  dashes and case are normalised; a page passes only if every box text appears exactly, the header is present and
  nothing else is lettered. Failed pages are repainted with a lettering correction up to 2 times; every painting,
  prompt and transcription is kept (`Page.painted`, the DirectorRun); the best is pre-selected; never auto-approved.
- The selected painting IS the page artifact: the render and the PDF place it full-bleed (170×260 mm + 3 mm bleed,
  crop marks in print), Topaz-upscaled when the export asks for upscaling.
- "Edit box text" (Director → run) validates the new text, then re-runs only the repaint + text check.
- Without keys the page is a PIL parchment placeholder with the box texts lettered, flagged as unproven.

Routes: `GET /api/art-director/painted/style`, `PUT /api/art-director/volumes/{id}/mode`, `PUT /api/art-director/pages/{id}/mode`,
`GET /api/art-director/pages/{id}/painted`, `POST …/painted/select`, `POST …/painted/verify`, `POST …/painted/boxes`.
